From this exact state, do this in order and do not improvise.

Your screenshot means two things: the VirtualBox share is still not mounted, and Autopsy is not installed into ~/autopsy yet. Shared folders in Linux guests depend on Guest Additions, and Autopsy’s Linux install path is: prerequisites, The Sleuth Kit, then Autopsy itself. For Autopsy 4.22.1, the correct ZIP is the _v2.zip and it uses Sleuth Kit 4.14.0.

1) Mount the VirtualBox share manually

Run this in the Debian terminal:

sudo VBoxControl sharedfolder list
sudo mkdir -p /mnt/shared
sudo mount -t vboxsf DF_Shared /mnt/shared
ls -lh /mnt/shared
ls -lh /mnt/shared/lubuntu_forensic.dd

If the first command shows the share name is not DF_Shared, rerun the mount command with the exact name it shows.

2) Replace the broken symlink with a clean one

Run:

rm -f ~/lubuntu_forensic.dd
ln -s /mnt/shared/lubuntu_forensic.dd ~/lubuntu_forensic.dd
readlink -f ~/lubuntu_forensic.dd
ls -lh ~/lubuntu_forensic.dd

At the end of this step, readlink -f ~/lubuntu_forensic.dd must resolve to:

/mnt/shared/lubuntu_forensic.dd
3) Remove the wrong Sleuth Kit package and install the correct one

You currently have sleuthkit-java_4.12.1-1_amd64.deb, which is the wrong version for Autopsy 4.22.1. The 4.22.1 release notes say it uses Sleuth Kit 4.14.0, and the release notes also say the correct ZIP is the _v2.zip build.

Run:

sudo apt remove sleuthkit-java -y || true
rm -f ~/sleuthkit-java_4.12.1-1_amd64.deb
wget -O ~/Downloads/sleuthkit-java_4.14.0-1_amd64.deb "https://github.com/sleuthkit/sleuthkit/releases/download/sleuthkit-4.14.0/sleuthkit-java_4.14.0-1_amd64.deb"
4) Install Autopsy properly

You already have:

~/autopsy-4.22.1
~/autopsy-4.22.1_v2.zip

Autopsy’s Linux instructions say to run the prerequisites script, install The Sleuth Kit .deb, then run install_application.sh, and that the prerequisites script gives you the Java 17 path to use.

Run:

cd ~/autopsy-4.22.1
chmod u+x linux_macos_install_scripts/*.sh
./linux_macos_install_scripts/install_prereqs_ubuntu.sh
sudo apt install ~/Downloads/sleuthkit-java_4.14.0-1_amd64.deb -y
update-java-alternatives -l | grep 17
./linux_macos_install_scripts/install_application.sh -z ~/autopsy-4.22.1_v2.zip -i ~/autopsy -j /usr/lib/jvm/java-17-openjdk-amd64

If update-java-alternatives -l | grep 17 shows a different Java 17 path, use that path instead of /usr/lib/jvm/java-17-openjdk-amd64.

5) Launch Autopsy

Run:

~/autopsy/bin/autopsy --nosplash

Autopsy’s Linux instructions explicitly recommend --nosplash on first run because the initial window can appear behind the splash screen and make it look stuck.

6) Add the image in Autopsy

Inside Autopsy:

Create a new case
Add Data Source
Choose Disk Image / VM File
Select:
/mnt/shared/lubuntu_forensic.dd

Do not use /media/sf_DF_Shared/... now. Your current path is the manual mount under /mnt/shared.

7) Final verification block

Before opening Autopsy, this block must succeed:

ls -lh /mnt/shared/lubuntu_forensic.dd
readlink -f ~/lubuntu_forensic.dd
ls -l ~/autopsy/bin/autopsy

The correct end state is:

/mnt/shared/lubuntu_forensic.dd exists
~/lubuntu_forensic.dd resolves to /mnt/shared/lubuntu_forensic.dd
~/autopsy/bin/autopsy exists

Run Step 1 exactly as written and stop only if ls -lh /mnt/shared/lubuntu_forensic.dd still fails
