Do this exact sequence from your **current** state.

Your screenshot shows two hard facts: `~/lubuntu_forensic.dd` is **not** a real local file, it is a symlink to `/mnt/shared/lubuntu_forensic.dd`, and `~/autopsy/bin/autopsy` fails because Autopsy has **not** been installed into `~/autopsy` yet. Shared folders in a Linux guest require **Guest Additions**, and Autopsy on Linux needs the **ZIP**, the matching **Sleuth Kit Java `.deb`**, and a **Java 17** install. For Autopsy 4.22.1, the correct pairing is the **`_v2.zip`** plus **Sleuth Kit 4.14.0**. ([Oracle Docs][1])

### 1) In VirtualBox, fix the share on the host side

Open the VM settings or the running VM **Devices** menu and make sure the host folder is shared as:

* **Name:** `DF_Shared`
* **Auto-mount:** on
* **Make Permanent:** on

VirtualBox supports creating the share from VM settings or from the running VM’s **Devices** menu, and Linux guests access it through Guest Additions. ([Oracle Docs][1])

### 2) In the running VM window, insert Guest Additions

In the VM window menu:
**Devices → Insert Guest Additions CD Image…**

Then in the Debian terminal, run this block exactly:

```bash
sudo apt update
sudo apt install build-essential dkms linux-headers-$(uname -r) -y
sudo sh "$(find /media/cdrom0 -maxdepth 3 -name 'VBoxLinuxAdditions.run' | head -n1)"
sudo usermod -aG vboxsf $USER
sudo reboot
```

That installs Guest Additions, adds your user to `vboxsf`, and reboots. Shared folders use Guest Additions, and Linux guest access is typically controlled through the `vboxsf` group. ([Oracle Docs][1])

### 3) After reboot, verify the `.dd` file is visible from the shared folder

Run:

```bash
ls -lh /media/sf_DF_Shared/lubuntu_forensic.dd
```

Now replace the broken symlink with a clean one:

```bash
rm -f ~/lubuntu_forensic.dd
ln -s /media/sf_DF_Shared/lubuntu_forensic.dd ~/lubuntu_forensic.dd
ls -lh ~/lubuntu_forensic.dd
readlink -f ~/lubuntu_forensic.dd
```

At this point, `readlink -f ~/lubuntu_forensic.dd` should resolve to:

```text
/media/sf_DF_Shared/lubuntu_forensic.dd
```

### 4) Remove the wrong Sleuth Kit Java package and get the correct one

You currently have `sleuthkit-java_4.12.1-1_amd64.deb`, which is the wrong version for Autopsy 4.22.1. Autopsy 4.22.1 uses **Sleuth Kit 4.14.0**, and the release notes explicitly say the correct ZIP is the **`_v2.zip`** because the original ZIP was linked to the wrong TSK version. ([GitHub][2])

Run:

```bash
sudo apt remove sleuthkit-java -y || true
rm -f ~/sleuthkit-java_4.12.1-1_amd64.deb
wget -O ~/Downloads/sleuthkit-java_4.14.0-1_amd64.deb "https://github.com/sleuthkit/sleuthkit/releases/download/sleuthkit-4.14.0/sleuthkit-java_4.14.0-1_amd64.deb"
```

### 5) Install Autopsy properly into `~/autopsy`

You already have `autopsy-4.22.1_v2.zip` and the extracted `autopsy-4.22.1` folder in your home directory. The official Linux instructions are: install prerequisites, install The Sleuth Kit `.deb`, then run `install_application.sh` with the ZIP path, install directory, and Java home. The same doc says Autopsy expects **Java 17**, and recommends `--nosplash` on first launch. ([Autopsy][3])

Run this exact block:

```bash
cd ~/autopsy-4.22.1
chmod u+x linux_macos_install_scripts/*.sh
./linux_macos_install_scripts/install_prereqs_ubuntu.sh
sudo apt install ~/Downloads/sleuthkit-java_4.14.0-1_amd64.deb -y
./linux_macos_install_scripts/install_application.sh -z ~/autopsy-4.22.1_v2.zip -i ~/autopsy -j /usr/lib/jvm/java-17-openjdk-amd64
~/autopsy/bin/autopsy --nosplash
```

### 6) In Autopsy, add the evidence image

Inside Autopsy:

* Create a new case
* Add Data Source
* Choose **Disk Image / VM File**
* Select:

```text
/media/sf_DF_Shared/lubuntu_forensic.dd
```

Do **not** use the broken old `/mnt/shared/...` path anymore. Use the real, working `/media/sf_DF_Shared/...` path.

### 7) If you want one single verification block before opening Autopsy

Run this:


The correct end state is:

* the `.dd` file exists at `/media/sf_DF_Shared/lubuntu_forensic.dd`
* `~/lubuntu_forensic.dd` resolves to that path
* `~/autopsy/bin/autopsy` exists

That is the one clean path from where you are now.
