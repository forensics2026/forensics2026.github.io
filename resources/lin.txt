### 2. Deleted File Recovery

**DO:**
- In File Analysis, look for filenames shown in **red** — these are deleted files
- Also run from terminal alongside Autopsy:
  ```bash
  fls -r -d /mnt/shared/lubuntu_forensic.dd
  ```
  This lists ALL deleted files with their inode numbers.
- To recover a specific deleted file:
  ```bash
  icat /mnt/shared/lubuntu_forensic.dd <inode_number> > ~/recovered_file
  ```
- Note down: filename, path, inode, file type, size

**SCREENSHOT:** The Autopsy file browser showing red (deleted) entries, OR the `fls` terminal output.

**WRITE:**

### 4. File Signature / Mismatch Analysis

**DO:**
- Muhammad found JPEG files saved as .dll using OSForensics mismatch search
- In Autopsy, navigate to wherever those files are and click on them
- Use the **hex viewer** tab to check the file header (JPEG starts with `FF D8 FF`)
- Alternatively from terminal:
  ```bash
  file /path/to/suspicious.dll
  ```
  This will say "JPEG image data" if the extension is faked.
- Also try:
  ```bash
  sorter -e /mnt/shared/lubuntu_forensic.dd
  ```
  `sorter` (part of Sleuth Kit) categorises files by type and flags extension mismatches.

**SCREENSHOT:** The hex view of a mismatched file showing JPEG magic bytes, or `sorter` output.

**WRITE:**

Both OSForensics and Autopsy identified the same key evidence and artefacts from the suspect image. Table [X] compares the two tools.

| Criterion | OSForensics | Autopsy (TSK) |
|-----------|------------|---------------|
| Platform | Windows (GUI) | Linux (web-based GUI + CLI) |
| Image Format Support | E01, dd, VMDK | dd, raw (via Sleuth Kit) |
| File Mismatch Detection | Built-in search function | Manual or via `sorter` utility |
| Deleted File Recovery | Built-in with GUI | Visual (red highlight) + `icat` CLI |
| Timeline Analysis | Limited | Built-in File Activity Timelines |
| Keyword Search | Built-in indexed search | Grep-based keyword search |
| Performance | Crashed during deleted file search and carving | Stable on 2 GB RAM due to lightweight web interface |
| Ease of Use | Point-and-click, minimal setup | Requires terminal setup, browser-based interface |

OSForensics provided a more intuitive interface for file browsing and mismatch detection but experienced stability issues on the constrained VM, crashing during deleted file search and file carving operations. Autopsy ran reliably on the 2 GB Debian VM due to its lightweight web-based architecture and allowed for deeper investigation through direct access to Sleuth Kit CLI tools such as `fls`, `icat`, and `sorter`.
