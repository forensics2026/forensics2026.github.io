You’re making this harder than it needs to be.

The screenshot shows lubuntu_forensic.dd is already sitting in your home directory. So unless that file is just a symlink, you do not need the shared folder to test Autopsy in Debian.

Fastest path right now

Run these exact commands:

ls -l ~/lubuntu_forensic.dd
readlink -f ~/lubuntu_forensic.dd
ls -lh ~/lubuntu_forensic.dd

If readlink -f prints /home/vboxuser/lubuntu_forensic.dd, then it is a real local file.

At that point, stop messing with Guest Additions for now and just launch Autopsy against the local file:

~/autopsy/bin/autopsy --nosplash

Then in Autopsy:

Create Case
Add Data Source
Choose Disk Image / VM File
Select:
/home/vboxuser/lubuntu_forensic.dd

That is the quickest way to prove whether Autopsy itself works in the Debian VM.

What went wrong in your screenshot

Three separate mistakes:

You typed udo instead of sudo
/media/cdrom is a symlink to cdrom0
Your find command was mangled

So if you still want to install Guest Additions properly, do this cleanly.

Shared-folder / Guest Additions route

First check the CD contents properly:

ls -lah /media/cdrom0

Then look for the installer:

find /media/cdrom0 -maxdepth 2 -name "VBoxLinuxAdditions.run" 2>/dev/null

If it finds the file, run it:

sudo sh /media/cdrom0/VBoxLinuxAdditions.run

Then reboot:

sudo reboot

After reboot:

groups
ls -lh /media
ls -lh /media/sf_DF_Shared
ls -lh /media/sf_DF_Shared/lubuntu_forensic.dd

If sf_DF_Shared exists but access is denied:

sudo usermod -aG vboxsf $USER
sudo reboot

Then check again:

ls -lh /media/sf_DF_Shared/lubuntu_forensic.dd
