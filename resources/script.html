STEP 01

Set Up a Shared Folder (Host ↔ Forensic VM)

You need a shared folder so your forensic VM (SIFT, Kali, CSI Linux, etc.) can access the VMDK evidence files sitting on your Windows host.

1.1 — Create the Shared Folder on Windows

  1. On your Windows Desktop, create a new folder: C:\DF_Shared
  2. Copy (do NOT move) the entire Source\images folder contents into it:
C:\DF_Shared\Lubuntu 64-bit-s001.vmdk
C:\DF_Shared\Lubuntu 64-bit-s002.vmdk
C:\DF_Shared\Lubuntu 64-bit-s003.vmdk
C:\DF_Shared\Lubuntu 64-bit-s004.vmdk
C:\DF_Shared\Lubuntu 64-bit-s005.vmdk
C:\DF_Shared\Lubuntu 64-bit-s006.vmdk
C:\DF_Shared\Lubuntu 64-bit.vmdk          ← descriptor file

1.2 — Add Shared Folder in VMware

  1. Open VMware Workstation/Player → select your forensic VM (not the evidence VM)
  2. Go to VM → Settings → Options → Shared Folders
  3. Set to Always Enabled
  4. Click Add → Browse to C:\DF_Shared → Name it DF_Shared
  5. Check Enable this share → Click OK

1.3 — Access the Shared Folder Inside your Linux Forensic VM

# VMware mounts shared folders here:
ls /mnt/hgfs/DF_Shared/

# If /mnt/hgfs/ is empty, run:
sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other

# Verify you can see the files:
ls -lh /mnt/hgfs/DF_Shared/

You should see all 6 VMDK segments and the descriptor file listed.

1.4 — Alternative: VirtualBox Shared Folder

# In VirtualBox: Devices → Shared Folders → Add → path to C:\DF_Shared, name: DF_Shared, Auto-mount

# Inside the Linux VM:
sudo mount -t vboxsf DF_Shared /mnt/shared
# or it auto-mounts to:
ls /media/sf_DF_Shared/
FIX Fixing Shared Folder for VirtualBox + Debian
THE PROBLEM

Running ls /mnt/hgfs/DF_Shared will fail — /mnt/hgfs/ is a VMware-only path. VirtualBox uses a completely different driver (vboxsf mount type). Your F20FO-Debian VM runs on VirtualBox, so Guest Additions must be installed first.

Confirmed setup: Windows 11 host, Oracle VirtualBox, Debian 13 VM (2 GB RAM, 25 GB disk). Shared folder C:\DF_Shared configured with Full Access and Auto Mount.

THE FIX — Run inside your Debian VM 
# 1. Install build tools
sudo apt-get update
sudo apt-get install -y build-essential dkms linux-headers-$(uname -r)

# 2. In VirtualBox menu: Devices → Insert Guest Additions CD image...

# 3. Mount and run installer
sudo mkdir -p /mnt/cdrom
sudo mount /dev/cdrom /mnt/cdrom
sudo /mnt/cdrom/VBoxLinuxAdditions.run

# 4. Add your user to the vboxsf group (CRITICAL)
sudo usermod -aG vboxsf vboxuser

# 5. Reboot
sudo reboot
AFTER REBOOT

Your shared folder will be accessible at:

ls /media/sf_DF_Shared/
STEP 02

Combine the Split VMDK into a Single Raw Disk Image

Your evidence is a split VMDK (6 segments). You must combine them into one single raw image before dc3dd can process it.

Method A — Using qemu-img

✓ Recommended 
# Install qemu-utils if not present
sudo apt-get install qemu-utils -y

# Convert the split VMDK to a single RAW image
# Point to the DESCRIPTOR file (Lubuntu 64-bit.vmdk), NOT the segments
qemu-img convert -f vmdk -O raw \
  "/mnt/hgfs/DF_Shared/Lubuntu 64-bit.vmdk" \
  /home/$(whoami)/evidence/lubuntu_combined.raw
IMPORTANT: Always point to the descriptor file (Lubuntu 64-bit.vmdk — the small 1.1 KB file), NOT the segment files. The descriptor file tells qemu-img how to read all 6 segments in order.

Method B — Using vmware-vdiskmanager

If Available 
# This tool comes with VMware Workstation (not Player)
vmware-vdiskmanager -r "Lubuntu 64-bit.vmdk" -t 0 lubuntu_combined.vmdk

# Then convert to raw:
qemu-img convert -f vmdk -O raw lubuntu_combined.vmdk /home/$(whoami)/evidence/lubuntu_combined.raw

Create the Output Directory First

mkdir -p /home/$(whoami)/evidence
mkdir -p /home/$(whoami)/forensic_images

Verify the Combined Image

# Check the file size — should be roughly equal to the total VM disk size
ls -lh /home/$(whoami)/evidence/lubuntu_combined.raw

# Check the partition table
sudo fdisk -l /home/$(whoami)/evidence/lubuntu_combined.raw

Expected output: You should see partition entries (likely a Linux ext4 partition + possibly swap).

STEP 03

Hash the Original Evidence (Pre-Imaging Baseline)

Before you create the forensic image, compute hashes of the original combined raw file. This is your baseline for chain of custody.

# MD5 hash
md5sum /home/$(whoami)/evidence/lubuntu_combined.raw | tee /home/$(whoami)/evidence/original_hashes.txt

# SHA-256 hash (append to the same file)
sha256sum /home/$(whoami)/evidence/lubuntu_combined.raw | tee -a /home/$(whoami)/evidence/original_hashes.txt

# View the recorded hashes
cat /home/$(whoami)/evidence/original_hashes.txt

Sample output:

a1b2c3d4e5f6... /home/user/evidence/lubuntu_combined.raw   (MD5)
f6e5d4c3b2a1... /home/user/evidence/lubuntu_combined.raw   (SHA-256)
Record these hashes in your Chain of Custody document.

STEP 05

Create the Forensic Image with dc3dd

dc3dd is an enhanced version of dd developed by the US Department of Defense Cyber Crime Center (DC3) — it adds built-in hashing, progress display, error logging, and split output capabilities.

5.1 — Basic Forensic Imaging Command

dc3dd if=/home/$(whoami)/evidence/lubuntu_combined.raw \
      of=/home/$(whoami)/forensic_images/lubuntu_forensic.dd \
      hash=md5 \
      hash=sha256 \
      log=/home/$(whoami)/forensic_images/dc3dd_imaging.log
ParameterWhat It Does
if=Input file — the source evidence (your combined raw image)
of=Output file — the forensic image destination
hash=md5Computes MD5 hash during imaging (no separate step needed)
hash=sha256Computes SHA-256 hash during imaging (stackable)
log=Saves a complete log of the operation (timestamps, hashes, byte counts, errors)

5.2 — Advanced Command with All Options

dc3dd if=/home/$(whoami)/evidence/lubuntu_combined.raw \
      of=/home/$(whoami)/forensic_images/lubuntu_forensic.dd \
      hash=md5 \
      hash=sha256 \
      hlog=/home/$(whoami)/forensic_images/dc3dd_hashes.log \
      log=/home/$(whoami)/forensic_images/dc3dd_imaging.log \
      rec=off \
      ssz=4096
Extra ParameterWhat It Does
hlog=Saves only the hash values to a separate file (cleaner for chain of custody)
rec=offDisables error recovery (skips bad sectors instead of retrying — faster)
ssz=4096Sets the sector size to 4096 bytes (matches modern disk sector sizes)

5.3 — Splitting the Output (Optional)

If you need the output split into smaller chunks (e.g., for storage on FAT32 drives):

dc3dd if=/home/$(whoami)/evidence/lubuntu_combined.raw \
      of=/home/$(whoami)/forensic_images/lubuntu_forensic.dd \
      ofsz=2G \
      hash=md5 \
      hash=sha256 \
      log=/home/$(whoami)/forensic_images/dc3dd_imaging.log

ofsz=2G splits the output into 2 GB chunks (.000, .001, .002, etc.)

STEP 06

Verify the Forensic Image (Post-Imaging)

After dc3dd finishes, it prints the input/output hashes. You must verify they match.

6.1 — Check the dc3dd Log

cat /home/$(whoami)/forensic_images/dc3dd_imaging.log

Look for lines like:

md5(if):    a1b2c3d4e5f6...
md5(of):    a1b2c3d4e5f6...    ← MUST match the input hash
sha256(if): f6e5d4c3b2a1...
sha256(of): f6e5d4c3b2a1...   ← MUST match the input hash
CAUTION: If the if and of hashes do not match, the image is corrupted. You must re-image.

6.2 — Independent Hash Verification

Don't just trust dc3dd's own log — verify independently:

# Hash the forensic image independently
md5sum /home/$(whoami)/forensic_images/lubuntu_forensic.dd
sha256sum /home/$(whoami)/forensic_images/lubuntu_forensic.dd

# Compare with the original hashes
cat /home/$(whoami)/evidence/original_hashes.txt

All four should match:

  1. Original evidence hash (Step 3)
  2. dc3dd's input hash (from log)
  3. dc3dd's output hash (from log)
  4. Independent verification hash (Step 6.2)

dc3dd vs dd — Why dc3dd Is Better for Forensics

dd  (standard)

  • ✗ No built-in hashing (manual md5sum needed)
  • ✗ No progress bar (silent by default)
  • ✗ No logging
  • ✗ Stops on error
  • ✗ No split output
  • ✗ Manual verification only
  • ○ General purpose

dc3dd  (forensic)

  • ✓ On-the-fly MD5 / SHA-256 hashing
  • ✓ Shows progress bar
  • ✓ Full operation log
  • ✓ Configurable error handling (rec=on/off)
  • ✓ Split output (ofsz= parameter)
  • ✓ Automatic input vs output hash comparison
  • ✓ Developed for forensics by US DoD DC3
